# Handoff to `@apple`, 2026-11-16

From `@linux`, the Linux commander. Everything the Apple commander needs to know about today's changes, in one place. Pull `main` first. Delete this file once every item is done or moved to `TODO.md`.

## 1. Who's who: AGENTS.md

- You're `@apple`, the Apple commander. You own `apps/apple/` and the Apple build version, and you keep `engine/swift/` as the reference build.
- Agents talk through `PLAN.md`, `TODO.md` and `BUGS.md` lines that start with a handle in backticks. On every start, pull and run ``git grep -n '`@apple`'``.
- An agent edits only what it owns, plus the shared parts (specs, `config/`, `fixtures/`, `spec.json`, `design/`, root docs). For anything else, file a mention.
- Please add the Mac checkout's real path to your row in `AGENTS.md`.

## 2. Two versions: PORTING.md › Versions

- `cribbage/minigames/spec.json` holds `specVersion`, now 1, covering rules r23. Bump it whenever a port would have to change something: an action, event, field, fixture, config shape, record encoding or scene behaviour. A rules version bump always bumps it too.
- `MARKETING_VERSION` is now the Apple build's version only.
- `spec.test.js` fails if `spec.json` is behind `config/rules.json`, or if the status lines of engine.md, ui.md or PORTING.md don't name the spec version.

## 3. The new layout: PORTING.md › Layout

Shared code under `engine/`, one folder per platform under `apps/`. Do the move in one patch build, following PORTING.md › Layout › Moving there:

- `swift/Package.swift`, `Sources/` and `Tests/` go to `engine/swift/`; `swift/App/` goes to `apps/apple/`. Use `git mv`.
- `scripts/debug.sh` and `release.sh` go to `apps/apple/scripts/`. `scripts/check.sh` stays, and runs only what the machine can run: the Mac skips Linux checks.
- The current `CHANGELOG.md` becomes `apps/apple/CHANGELOG.md`, with a new `apps/apple/README.md`. The top-level `CHANGELOG.md` then lists spec changes only.
- Paths that count folders: the `#filePath` test paths gain one `../`, the simulator's default `--config` becomes `../../cribbage/minigames/config`, and `project.yml`'s package path and resource paths change.
- Other paths to `swift/`: `.claude/commands/debug*.md`, `.claude/hooks/check-version-bump.sh`, `.gitignore`, `spec.test.js`, and the docs (`git grep -n "swift/"`).
- The version hook checks per platform: `apps/apple/` or `engine/swift/` needs an Apple bump, and `apps/linux/` needs a Linux bump.
- Check: `scripts/check.sh` passes, `/debug` runs the beta, and the golden records verify. Then delete the Moving there subsection.

## 4. The engine is shared now, and must keep building on Linux

The Swift engine builds and passes all 68 tests on Linux ARM64 with Swift 6.4.2, with no code changes, golden records byte for byte (PORTING.md › Swift, on Linux or Windows). The Linux client links it by path, so:

- Keep the package name `CribMazeEngine` and its library names: GameKit, CardKit, CribbageKit, CribMaze, CribMazeBots, GameRecord.
- Keep it Foundation only: nothing Apple-only. Before adding actors or async code, file a `` `@linux` `` item: Godot calls the engine from its main loop.
- If an API the clients use changes (`GameRun.start`, `RecordReader`, `Replayer`, `Config.load`), file a `` `@linux` `` item in `TODO.md`.

## 5. The Linux side

- `apps/linux/` will hold a Godot 4.7 project and a Swift extension (SwiftGodot). Mac agents don't edit it.
- The Linux VM sees the Mac's checkout at `/mnt/mac` but never builds or commits there. All Linux work arrives through `main`.

Show the build line (`Mac 0.15.x · spec 1 · r23`) on the About screen, and add `specVersion` to the record header with engine.md › Records updated. The header change is a format change, so it bumps the spec version.
